# 個人情報チェック＋機密情報の追加スイッチ

更新：2026-10-31。ライト・スタンダード・フルセキュアの3択を廃止し、基本の個人情報チェックと「機密情報もチェックする」スイッチへ整理しました。旧3レベルの関数とテストは互換性・回帰確認用に残しています。

## 処理と本人の選択

- オフ：正規化・ルール＋専用PIIモデルで個人情報を確認。候補は初期選択されます。一般の金額・予定・役職や、未公開計画の文全体は勝手に伏せません。
- オン：上記の個人情報チェックをした上で、端末内Qwen2.5-1.5Bで文単位の機密候補を追加確認します。未公開の指定はルールでも補います。
- 機密候補は原文・確認する理由・検出元をカードで表示します。候補は初期状態では未選択です。「この範囲を隠す」で選んだ範囲だけを置換します。
- 個人情報と機密文が重なるときも、個人情報の選択を維持します。機密範囲の選択を解除しても、その中の個人情報は残して保護します。
- 未選択の機密候補は原文のまま加工文に残り、件数と注意を表示します。「すべて置換」でまとめて選ぶこともできます。
- 機密内容を自動で一般化したり、別の事実や数値に書き換えたりはしません。選んだ箇所を一貫したラベルに置換し、対応表をタブ内で保持します。
- 名寄せ・手動追加・AI回答の復元は継続。名寄せ時は個人情報を初期選択、機密候補を未選択に戻すことを画面に明記しています。

## 理由の根拠

文脈AIは全文を受け取り、既存の文IDごとに public または review（確認候補）を返します。全てのIDが存在し、未知のID・分類・余分なキーがないか端末内で検証します。
理由は非公開指定や、候補文に含まれる「独自の工程」「顧客」「人事」等の手がかりに対応する定型説明です。手がかりのない候補は文脈AIによる確認候補であると説明します。AIが自由に書いた根拠を事実として表示する方式ではありません。「未公開の計画の可能性」等の確認理由であり、法的な秘密性の断定ではありません。
分類が不正・範囲が不足・モデルの処理が失敗した場合は確認未完了としてコピーを無効にします。

## 通信と環境

検出・分類・置換・復元は全てブラウザーのタブとWorker内です。入力をサーバーや外部推論APIへ送りません。初回にはモデルの取得通信があり、モデルはブラウザーにキャッシュされます。
個人情報用AIにはGPUとCPUの経路があります。機密情報用AIはWebGPUが必要で、全スマホ・ブラウザーでの動作を保証しません。機密情報の確認が失敗しても黙ってPIIのみの成功扱いにはせず、スイッチをオフにして再チェックする選択肢を示します。
「ルールのみ」を本人が選んだ場合はAIを実行せず、機密情報は明示された非公開指定に限定することを結果に表示します。

## 評価対象

個人情報と機密文の重なり、機密候補の選択と解除、複数候補の個別選択、一般論・公開済みの陰性例、分類と説明の対応、不正な分類の拒否をテストします。専用PIIモデルの検証記録は LIGHT_EVALUATION.md にあります。旧検証記録は今回のQwen分類精度を示すものではありません。

## 今回の実ブラウザー確認（2026-10-31）

WebGPU対応のCodex内ブラウザーで、専用PIIモデルと機密情報AIを順に実行しました。全て架空の名前・例文です。

- 名前・メール＋未発表の新製品計画＋映画の趣味：名前とメールを初期選択、計画を理由付き未選択候補にし、趣味文は候補にしないことを確認。
- 名前＋独自の歩留まり改善方法＋通常の会議と料理：製造方法を端末内AIのみの候補にし、通常の仕事・料理の文は残すことを確認。
- 機密候補を選択すると、その文を非公開情報ラベルに置換。模擬回答を貼り付け、そのラベルを元の文へ復元することを確認。
- 同じ入力でスイッチをオフにすると、名前だけを置換し、製造方法の文はそのまま残ることを確認。設定変更時は古い結果・対応表・コピーを無効化。

小規模な操作確認であり、機密情報全般の検出精度や安全性を保証するものではありません。実装途中の多分類方式では映画の趣味を誤検出したため、今回の公開版は既存の public/review 判定を使用し、理由は原文の手がかりに基づく定型文で補います。既存の LOCAL_AI_EVALUATION.md に記録した見落とし・誤検出の限界も引き続きあります。
