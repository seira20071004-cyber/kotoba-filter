# 2モードと確認操作・検出の改善

## 変更

- 画面は「通常」と「機密情報も隠す」の二つ。既定は通常で、従来のスタンダード相当。ライトは画面から削除。内部API名 `standard` / `full` と過去互換の検出関数は維持する。
- 検出した値と保護範囲は初期選択。原文マーキングと折りたたんだ詳細で必要な箇所だけ選び直せる。一般化する範囲も、選んだモードの対象として初期選択する。
- 未確定の範囲は「自動では隠していない候補」としてまとめる。理由は任意に開ける。一件ずつの「内容を残す」操作を廃し、一つの確認欄で未加工部分が残ることを明示的に確認する。加工文を変えたらこの確認状態をリセットする。確認は保護成功を意味せず、原文の内容は残りうる。
- 文字位置・形式の不正や推論そのものの失敗は完了扱いにしない。コピーを止め、再実行または本人によるルールのみの選択を必要とする。未確定候補と実行失敗を混同しない。
- 数量・在庫・出荷・販売・商品名・製品名の業務文脈を追加。セット・箱・重量・漢数字等の数量を補助検出する。年間・以上・以下・未満は数量の外に残す。
- 商品名・製品名の明示フィールド、商品や納品の文脈にある引用符付きの名称を補助検出する。自由記述中の全ての商品名を推定できるわけではない。
- 商品名・固有名詞を入力欄の近くで明示的に指定できる。1〜80文字・20件・タブ内のみ。原文中の一致を全て対象にするため、短すぎる語の指定には注意が必要。個別の出現だけを隠す場合は結果の手動指定と選択を使う。
- 自動のPII判定・文脈判定で句読点・括弧・矢印・記号・空白だけのノイズを抑制。助詞だけの人名候補も抑制する。一文字の実名や本人の明示指定、記号を含む認証情報を一律に捨てない。
- 値がPII等との重なりで分割されても、全体を選択した値は一つのラベルへまとめる。原文位置と復元の整合性を維持する。
- 900px以下では一列にし、チェック完了後は結果へスクロールする。

## 検証

- 自動テスト158件成功。今回追加14件。既存の通常・機密保護・原文範囲・復元・未知のAI文ID・失敗時コピー停止も含む。
- 型チェック `npx tsc --noEmit` 成功。
- 実GPUで専用PIIモデルとQwenを実行。通常モード7例を確認。商品名、数量、漢数字、しきい値、明示登録、記号の例は自動保護後にコピー可能で、残存する健康・法的事情の例だけ追加確認を必要とした。
- 残存2候補に対して一度の確認でコピーできること、手動で加工すると確認が外れてコピーが止まることを確認。
- 「機密情報も隠す」モードで、健康情報を含む質問先行の文、記号だけの文、商品名と数量の3例を確認。
- 実測は `docs/evaluations/two-modes-2026-11-03/`。`browser-first.json` には保護済みの数量・登録語への重複確認が残っていた途中の結果も含む。最終版では限定した説明・依頼の判定を追加した。入力は全て合成例で、独立した精度評価ではない。

## 残る限界

商品名を含む全ての固有名詞や企業ごとの秘密を網羅するものではない。登録した語は部分一致・正規化・ASCII大小文字の扱いに従うため、意図しない場所も隠すことがある。必要なら原文上で選択を調整する。確認を一回にまとめても、残した候補が外部へ出てよいとアプリが判定するわけではない。

今回の検証はGPU環境。CPU・スマートフォン等へ同じ性能を適用できず、文脈AIにはWebGPUが必要。検出の失敗時に無言でルールへ切り替えない。原文・対応表を外部推論APIへ送らない構成と、タブ内のみで扱う方針は維持している。
