# フルセキュア

調査から得た利用場面をもとに、フリーランス・小規模事業者の相談文から、値だけでなく特定につながる背景や非公開の事実を減らすモード。既定はライト。本人がフルセキュアを選び、候補と加工文を確認して使用する。

## 動作

- 個人情報のルール・専用モデル、スタンダードの業務値ルールを維持する。
- 地域で唯一の業種、家族関係、事業規模など、特定につながる珍しい背景を検出する。背景が特定可能であることの証明や、公開情報との照合は行わない。
- Qwen2.5-1.5Bを端末内で実行し、既存の文IDごとの公開/要確認判定を追加する。入力中の命令はデータとして扱い、欠けた文IDや未知の判定は失敗とし、コピーを無効にする。
- 機密の可能性がある事情・計画・技術情報・個人の事情は、値だけではなく、内容を含む文や句を隠す候補にする。
- 限定した書式の閉店・撤退の理由、健康・家庭の理由、役職・親族関係は、あらかじめ定義した一般表現に言い換える候補を示す。AIが自由に生成した言い換えは使わない。
- 候補ごとに原文・理由・加工後の表現を表示。隠す/一般化する/残すは本人が選択する。未確認候補のままコピーしない。
- 依頼だけの文や句を切り分け、質問が先にある場合も後続の事実を独立して検出する。切り出せない場合は質問も隠れる可能性があり、意味の保持を保証しない。
- 同じ文に別のセンシティブな事実が残るときは、一部の一般化だけで保護済み扱いにしない。
- 明示的な一般論・架空の設定は既存の文脈ポリシーで除外し、実際の事実や非公開指定があれば一律には除外しない。

## 例

入力：
県内唯一の医療機器専門店で、創業者の長女が経理を担当しています。その人から、来月閉店するので契約を打ち切りたいと言われました。どう返事すればよいですか？

候補を保護した加工文：
特定につながる詳しい背景は省略します。その人から、事業上の事情により契約を打ち切りたいと言われました。どう返事すればよいですか？

これを全般的な自由記述の要約・言い換えを行うモデルとして解釈しないこと。上記は、該当する文型・背景のルールで一般化する一例。

## 復元

PII・値・非公開情報など、種類付きラベルへの置換は従来どおり現在の対応表で復元可能。一般表現に言い換えた箇所は `restorable: false` とし、復元対象から除外する。同じ一般表現が回答に現れても、元の秘密へ自動で置き換えない。画面にも明記する。

## 境界

原文・対応表はタブ内のみ。外部推論API・アプリDBへ本文を送信しない。モデルと実行ライブラリーの取得通信・キャッシュはある。

名称は保護範囲の広さを表すもので、完全な漏洩防止・法的な匿名加工情報・NDA適合を保証しない。自由記述では見落とし・誤検出・相談に必要な意味の欠落がある。業務上の秘密を外部AIに入力してよいかは、加工後の文章についても利用者が判断する必要がある。

## 検証（今回）

- 自動テスト113件が成功。背景と事情の一般化、質問の保持、PIIが重なる範囲、部分選択、名寄せ後の範囲、一般表現の復元除外、否定文、別の機密が同じ文に残る場合、未知のAI文IDを確認。
- 実ブラウザーでPIIモデルとQwenを端末内GPUで実行し、背景・閉店事情の候補、未確認時のコピー停止、一般化後の契約相談・質問の保持、一般化のみの場合に復元欄を表示しないことを確認。
- 実モデルが、顧客向け検査の省略方針および非公開の独占合意を見落とすケースがあった。補助ルールを追加し、ブラウザーでも取引合意を隠して質問を残せることを確認した。これらは改善に使った合成ケースであり、未知の文章の検出精度の証明ではない。
- ルールのみの場合は、文脈AI未実行と表示する。モデルの検出範囲がルールと独立してすべての秘密を補完できるとは限らない。

## 文脈検出の改善（2026-11-02）

- `full-policy.mjs` で依頼・事実・公開説明を分け、正規化後から原文のUTF-16位置へ戻す。機密の話題が出るだけの依頼を機密と断定しない。依頼の文中に具体的な事実があれば除外しない。
- 端末内AIも同じ句の境界・ユニークな文IDで分類する。不正なIDや未完了の結果は従来通りコピーを停止する。
- 公開済みという説明、安全管理の助言、非公開指定のない通常営業の否定文は除外する補助判定を追加。公開状況を外部資料で検証する機能ではない。「資料に載っていない」という否定は公開済み扱いにしない。
- 支払能力、健康・家庭、法的事情、内部システムの弱点、具体的な人物の私的事情、内部の製品・運用説明を確認候補にする。ルールで検出した分類名を理由に表示する。
- 珍しい背景は同じ段落の最大3つの隣接した事実単位で組み合わせを見る。全文や別タブとの再特定リスクは評価しない。
- 後置された非公開指定は、同じ段落の直前1単位にも適用する。無制限に前へ遡らない。
- 役職だけの一般化後に、健康・法的事情等が残るなら範囲全体を保護候補にする。
- 数社・二社・他社や見出しの「電話番号」など、固有の識別値ではない限定した語の誤検出を抑制する。手動指定や機密キーワードは除外しない。

固定データの評価結果・失敗の経緯は `FULL_IMPROVEMENT_2026-11-02.md`。数値は開発用の合成例であり、未知の業務文の安全性を証明しない。
