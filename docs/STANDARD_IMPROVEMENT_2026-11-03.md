# スタンダード改善と完成度（2026-11-03）

## 現時点の位置付け

Web版を少人数で試し、手間と相談の有用性を検証する段階。完成したセキュリティ製品・無確認で機密を任せられる製品とは位置付けない。前日のフルセキュア68例は開発用データであり、スタンダードの未知の文章の検出率でも、実務の有用性の実証でもない。

今回の中心は、受託フリーランスの見積もり・納期・顧客返信の相談において、説明を残したまま値を隠し、既に保護した値への重複確認を減らすこと。

## 再現した問題と変更

| 問題 | 改善 |
| --- | --- |
| 「例えば、実際の見積金額は300万円で値引率は28%です」がルールでは無検出 | 単語だけの一般論判定をやめ、実際の事実・公開説明・架空設定を分ける |
| 「公開済みの資料には載っていませんが、見積額は42万円です」が公開済み扱い | 公開状況を否定する句を除外しない |
| 金額とシステムの弱点が同じ文にあり、金額だけ隠すと警告が消える | 値を除いた残りを確認し、既知のセンシティブな内容が残れば追加確認。自動で文全体を隠す処理は追加しない |
| AIが範囲をまとめて引用すると「300万円から350万円」「11月15日から12月20日」の関係まで隠れる | 金額・日付ごとに分離し、から・へ・に変更を残す |
| AIの型が誤っていても、原文中の普通の文を金額・日付等として採用する可能性 | 数値の種類と形式も検証。適合しない引用は値として採用せず確認対象にする |
| 値を隠せても純粋な依頼や定型説明に余分な警告が出る | 純粋な依頼と、値以外が限定した説明だけの文への重複警告を抑制。別の事実が残る場合は抑制しない |
| 実モデルで見積もり範囲の抽出が長引き、確認失敗 | 既知のルール値を同じ文字数のプレースホルダーにして端末内AIへ渡し、再抽出を省く。原文照合は未加工の文単位で行う。最終版で同じ例の完了を確認したが、一般的な速度・安定性の保証にはしない |

## 検証

- `npm test`：144件成功。追加16件を含む。従来のライト・スタンダード・フル、原文範囲と復元、未知のAI文ID、中止・失敗、コピー停止の回帰を含む。
- `npx tsc --noEmit`：成功。
- 実ブラウザーのGPUで、OpenAI Privacy FilterとQwen2.5-1.5Bを実行。
- 最終ロジックでスタンダード11例の確認が完了。残存機密の2例では追加確認までコピーボタンが無効になり、それ以外の9例では必要な選択後にコピーできた。これは精度9/11という意味ではない。
- フルの質問先行例、ライトで電話だけを隠して金額を残す例も実行。
- 残存機密を手動追加し、明示的な確認後にコピー可能になる操作を確認。入力の変更後は加工文が空になり、コピーが無効になることも確認。
- 合成文のみを使用。開発者が文章・期待値を作成し、改善にも利用した。独立した評価ではない。

実測JSONは `docs/evaluations/standard-2026-11-03/`。`browser-initial.json` には改善途中の重複警告と確認失敗の記録も残している。`browser-final.json` は最終ロジックの記録で、金額に関する理由文の表現微調整前。主にルールで検出した値を、AIが検出した成果として数えない。金額/日付の範囲をまとめて返した場合の分離は構造化したモデル出力を使う単体テストでも検証しており、実モデル単独の抽出精度とは区別する。

## 完成と呼ぶ前に必要な確認

1. 実際の受託業務で、手作業より匿名化の負担が減るか。別サイトに移動する負担も含めて測る。
2. 加工後でも、追加費用交渉や納期変更に役立つ回答が得られるか。質問文が残るだけでは有用性の証明にならない。
3. 次の案件でも本人が自発的に使うか。
4. GPU/CPU・ブラウザー・端末ごとの準備時間、推論完了率、誤警告の負担を独立した例で検証する。

金額の大小や期間が相談の核心なら、値を隠すことで判断材料が失われる。今回、相対値・近似値への自動変換や安全性の証明を実装したわけではない。利用者が残すか判断する必要がある。会社固有の秘密や未知の表現も網羅できず、残存検査で全ての見落としを捕捉できるわけではない。
