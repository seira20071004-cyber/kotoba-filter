# フルセキュア 自己評価（2026-11-02）

## 結論

現状は検証用プロトタイプ。文脈の秘密を取り除き、相談の意味も残すという目標は未達。既存の113件の回帰テスト通過は、自由記述の検出精度の証明ではなかった。

評価中に見つかった隣接候補の選択不具合は別途修正する。文脈検出・一般化の精度をこの評価データに合わせて調整してはいない。

## 条件

- 修正前の公開ソース：52f15a92bb6e58b1b79aba2d5931083c330fe2c2。
- 公開サイトのUIで24件を実行。PIIはOpenAI Privacy Filter / GPU、文脈はQwen2.5-1.5B / WebGPU。
- すべて架空の合成文。16件に21個の保護対象文字列を事前指定。8件は非機密として保持すべき文章。
- 今回新規に作成した例文だが、開発者による小規模な意図的テストであり、第三者による盲検や実利用者全体の無作為標本ではない。
- 候補が出た場合「候補をすべて保護する」を押した。本人が候補を見落とした・残した結果ではなく、用意された候補をすべて保護した場合の加工文を評価する。
- 文字列が出力から消えただけでは成功にしない。原文の全ターゲット範囲が実際に選択されたマーキングで覆われたことを確認。例：今月だけを隠し、透析の事情が残る場合は失敗。
- 相談の依頼文は別に保持を評価した。依頼文が残っても、回答に必要なすべての意味が保存された証明にはならない。
- ルール＋モデル＋範囲選択の総合結果であり、AI単体の適合率・再現率ではない。elapsedMsは操作間の待ちを含み、推論速度の指標として使わない。

## 修正前の結果

| 指標 | 結果 |
|---|---:|
| 全保護対象を選択できた機密ケース | 8 / 16 |
| 保護対象の範囲を全て選択できたターゲット | 11 / 21 |
| 非機密なのに加工されたケース | 5 / 8 |
| 指定した相談の依頼文を保持 | 19 / 24 |
| 全保護対象の保護と依頼文保持を両立 | 5 / 16 |

この件数を「実利用で50%の精度」などと一般化しない。対象の分類やサンプリング方法が異なる他製品・論文の数値と比較しない。

## 優先する改善

1. **範囲と確認状態の整合（今回修正）**：隣り合う同じ種類の候補を一つのマーキングへ結合すると、各候補の内部に収まる断片がなくなり、選択が反映されない。部分だけが選択されても保護済みと表示される場合がある。境界の維持、範囲全体の選択確認、コピー直前の検証が必要。
2. **意味の保持**：相談の目的を機密文から分ける。「告知文の構成を相談」「記事の見出しを考えて」等を隠さない。現在のキーワード・文型依存の限界がある。
3. **文をまたぐ文脈と残存リスク**：別々の文にある業種・家族関係・規模の組合せを確認する。役職を一般化しても逮捕等の事情が残るケースがある。
4. **見落としと誤検出を別々に改善**：婉曲な資金不足、健康状態、認可の不備、非公開の合意の別表現を評価する。公開ニュース、否定、注意喚起を機密と混同しない。未知の例文を別セットにし、同じ文型が学習用・評価用に重複しないようにする。

## 類似技術から参考にする点

比較は公式仕様・公開論文の調査。競合製品をこの24件で実測した精度比較ではない。

- [Prompt Anonymizer](https://github.com/akazah/prompt-anonymizer)：端末内処理、一貫したラベルと復元、日本語対応。評価データと再現手順を公開し、識別子を隠しても周辺文脈による特定が残ると明記。参考：[評価](https://github.com/akazah/prompt-anonymizer/blob/main/docs/EVAL.md)。社内の秘密一般を完全に理解する製品とは解釈しない。
- [Presidio](https://presidio.dataprivacystack.org/text_anonymization/)：PIIの検出器と加工処理を分離し、ルール・NER・チェックサム・周辺文脈を組み合わせる。[評価方法](https://presidio.dataprivacystack.org/evaluation/)は適合率・再現率・用途別の評価と、合成文の同じパターンが評価に混入しない分割を扱う。[検出の根拠の追跡](https://presidio.dataprivacystack.org/analyzer/decision_process/)も参考になる。根拠の説明は見落としの不存在の証明ではない。
- [Umbra](https://useumbra.org/docs)：Smart / Full / Offがあり、Fullは文脈を含む低確信のカテゴリも対象とする。段階的な保護やブラウザー内処理自体は独自ではない。公式にも未知の書式が通過し得ると明記している。
- [Casper（研究）](https://arxiv.org/abs/2408.07004)：ルール、NER、ブラウザー内ローカルLLMのトピック判定を組み合わせる。三段構成だけでは差別化にならない。論文の合成データでの成績を、日本語の自由記述や当アプリの性能へ転用しない。

## 差別化の候補

日本語の小規模事業者の具体的な相談で、漏らす情報を減らしながら必要な相談の目的を残せること。その達成は、機能の多さではなく、固定した事例と別の未調整データで評価する必要がある。


## 範囲選択の修正

- 検出元と種類が同じでも、異なる候補の境界をまたいでマーキングを結合しない。
- 「保護済み」は、候補の開始から終了まで、切れ目なくすべての範囲が選択されている場合だけにする。
- 「隠す」と確認した候補が実際に全範囲選択されていなければ、コピー直前にも停止する。
- 追加4件を含む117件の自動テストを実行。実ブラウザーで、1つ目だけの選択・2つとも選択した場合の本文とコピー可否を確認した。

上記の8/16等は修正前に固定した結果。修正で文脈AIの見落とし・過剰検出が改善したという意味ではない。
