# 端末内の機密情報チェック：調査・対象・限界

更新：2026-10-30。ここでいう分類はアプリの検出候補であり、法的な営業秘密該当性の判定ではありません。

## 正規化・パターン検出で足りないもの

正規化は全角や不可視文字などの表記をそろえる前処理です。情報が公開済みか、特定企業だけのノウハウか、誰の病気か、複数の発言から身元が分かるか、という意味は判定できません。

INPITは、技術・ノウハウ、実験データ、品質・設計基準、製造プロセス、作業マニュアル、仕入れ先・販売先などを情報資産の例に挙げています。
Microsoftのデータ分類ガイドは、分類が組織ごとの方針に依存すること、機微度・情報の種類・適用範囲を定めること、ツールだけに依存しないことを説明しています。
NISTのSP 1800-39初期ドラフトの紹介も、会話などの非構造化データを含めて機微な情報を発見・分類する必要性を扱っています。

## 今回の検出対象

| 候補の分類 | 例 | 正規表現だけで難しい理由 |
| --- | --- | --- |
| 未公開の事業・製品計画 | 開発中の機能、M&A、発売時期、社内の営業計画 | 普通の文章でも、公開状況や話者の所属で機密性が変わる |
| 技術・製造ノウハウ | 独自ロジック、配合、工程条件、実験や設計の知見 | 専門的でない言い回しにも価値ある知見が含まれる |
| 顧客・契約・取引条件 | 得意先、取引量、仕入れ先、個別価格、値引きや交渉 | 名前だけでなく取引条件そのものが非公開になり得る |
| 未公開の財務情報 | 社内予測、利益率、原価、資金繰り、調達交渉 | 公開決算と社内試算で扱いが違う |
| 人事・従業員情報 | 給与、評価、異動、退職・解雇の予定 | 個人名がなくても職場の文脈から特定できる |
| 法務・調査・社内事情 | 係争、和解交渉、内部通報、調査結果 | 固有の番号がなくても内容自体が非公開 |
| 認証・社内システム・脆弱性 | 認証の抜け道、内部構成、運用上の弱点 | パスワードの文字列がなくても漏えいリスクがある |
| 文脈上の個人情報 | 病気・家族事情、唯一の店での勤務、具体的な行動習慣 | 単語の一致だけでは、個人の事情か一般論かを区別しにくい |
| 情報の組み合わせ | 過去に話した所属＋現在の役割や日時 | 個々の文が無害でも特定の手がかりになる |
| その他の非公開情報 | 上記の分類に収まらない具体的な秘密 | 未知の分類を完全には列挙できない |

これらを**必ず検出できるという意味ではありません**。組織内での公開範囲や独自の呼び名は、モデルには分からない場合があります。

## 実装の層

1. 既存の正規化・連絡先などのパターン検出。
2. 明示された非公開指定（社外秘、未公表など）の文脈ルールと、このタブだけの機密キーワード。
3. WebLLMとQwen2.5-1.5B-InstructをWeb Worker内で実行。現在の本文を意味単位に分け、現在文の全単位IDについて、一般情報か要確認候補かを必ず返させる。
4. ID・分類・形式を検証し、原文の位置へ対応付ける。存在しないIDや不明な分類は採用しない。重なった範囲は結合する。
5. 本人が候補を選択して `[非表示]` にする。候補にない原文の語句も手動で追加できる。
6. 送信文を確認した後だけ、外部AIへ送る。未選択の候補は原文のまま送信される。

意味単位は最大320文字、1回のモデル入力は最大1,100文字・5単位で、隣接バッチに1単位の重なりを持たせます。本人の過去の送信文は直近2件・各160文字まで、端末内でのみ参照します。過去のすべての発言を監査したり、送信済みの文章を取り消したりする機能ではありません。
AIは文単位などの広い候補を返すことがあります。候補は確定した機密判定ではなく、確認を促す情報です。

## 準備失敗と対応端末

初期設定は「ルール＋端末内AI」。初回は大きなモデルの取得が必要で、WebGPUと空きメモリーを使います。
AIの準備前・確認中・失敗・不正な結果の状態では、そのモードの送信を許可しません。
対応しない環境でも、本人が明示的に「ルールのみ」を選ぶと確認を続けられます。その場合は端末内AI未実行と表示します。黙ってルールのみへ切り替えません。
確認を閉じると実行中の検出を中断し、遅れて来た結果を別の下書きへ適用しません。

## 保存と送信の境界

モデルの取得では配信先との通信が発生し、モデルファイルはブラウザー内にキャッシュされます。入力した原文をモデル配信URLやリクエスト本文へ付加するコードはありません。
原文・キーワード設定・解析結果は、このタブのメモリー内で扱います。アプリDBやlocalStorageへ保存しません。
キーワード設定は別途送信しません。ただし、その語句が送信文に含まれ、本人が非表示を選ばなかった場合は、文章の一部として外部AIへ送られます。
外部AIには、確認した送信文と既存の会話履歴だけを渡します。
`analysisMode` と `reviewVersion` は互換性・表示用の申告であり、端末内AIを実行したことをサーバーへ証明するものではありません。改変クライアントの利用者にAI実行を強制できるという説明はしません。

## 検証の区別

`tests/fixtures/confidential-cases.json` は合成した評価ケースです。全分類と、一般論・公開情報・日常会話などの陰性例を含みます。
自動テストは、原文の位置、バッチの範囲、結果形式の拒否、範囲結合、機密語・手動追加、旧クライアントの拒否、外部送信の境界を検証します。
**形式のテストに合格しても、モデルの意味理解の精度を保証しません。** 実モデルによる確認結果は別途記録します。
誤検出・見落とし、会社固有の情報、暗喩、長い会話、多言語・ソースコードなどの追加評価が必要です。
