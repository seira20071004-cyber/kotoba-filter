# Privacy Chat

AIと気軽に会話できる、個人情報チェックの開発用プロトタイプ。
現在は **第1段階：AIチャット** を実装しています。

## 今できること

- リンクからAIチャットを開始。登録プロフィールやマッチングは不要。
- 同じ会話の直近10往復を踏まえて返答。
- スマホ対応、改行、IME対応、送信中表示、新しい会話。
- 失敗時は入力文を復元。AIの返答を捏造した代替応答には切り替えない。
- 通常のフォーム送信を使わず、送信後も同じ画面に残る。
- 会話本文はタブのメモリー内のみ。localStorageやアプリDBに保存しない。

## 大切な制約

**個人情報の検出・マスキング・端末内AIチェックはまだ実装していません。入力文はそのまま外部AIに送信されます。**
画面にも明示し、本名・住所・カード番号などを入力しないよう案内しています。
AIのsystem指示で注意を促しても、送信前の情報保護にはなりません。

今後の順番は、入力 → 正規化＋ルール検出 → 端末内AIによる文脈検出 → 本人の確認・修正 → 外部AIへ送信。
正規化そのものは検出ではなく、全角・空白・不可視文字などを検出しやすい形にそろえる処理です。
チェック処理は会話APIから分離して追加し、AI未準備時の扱いは実装時に明確化します。

## 情報の流れ

ブラウザー → このアプリの認証済みAPI → OpenAI Responses API。
APIキーはサーバー秘密変数。ブラウザー・Git・配布アーカイブへ含めません。
送信は `store:false`。OpenAI側のすべての保存・監視を無効にする保証ではありません。
アプリDBはユーザーIDと日付ごとの利用回数だけを記録します。1人1日60回、1入力2,000文字、入力合計12,000文字、直近10往復まで。
公開環境はSitesの認証を使用し、匿名のAPI実行は拒否します。作成時は本人限定です。

## 開発

Node.js 24推奨（22.13以降のnode:sqliteが必要）。

```sh
npm ci
npm run dev:local
```

`http://127.0.0.1:5180/chat/` を開きます。ローカルは合成IDに固定し、localhostだけで待ち受けます。
OpenAI Developersの安全なキー設定フローで、このリポジトリの `.env.local` に `OPENAI_API_KEY` を設定します。ファイルはGit管理しません。
ローカルの利用回数は `.sites-runtime/chat-quota.sqlite` に保存します。

```sh
npm test
npx tsc --noEmit
npm run build
```

`public/chat/` がUI、`lib/chat.mjs` がプロバイダーと入力検証、`app/api/` が本番の認証とバインディング、`scripts/dev-chat.mjs` がローカル実行です。
GitHubへのpushとSitesへのデプロイは別です。秘密変数の更新後は再デプロイが必要です。
新しいAPIキーは作成時に選択した有効期間で失効します。今回の初期キーは24時間です。

参考：[OpenAI会話履歴のガイド](https://developers.openai.com/api/docs/guides/conversation-state)
