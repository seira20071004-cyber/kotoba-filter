# Privacy Chat

AIと気軽に会話できる、個人情報チェックの開発用プロトタイプ。
現在は **第2段階：正規化・ルール検出と、本人が選ぶ非表示** を実装しています。

## 今できること

- リンクからAIチャットを開始。登録プロフィールやマッチングは不要。
- 同じ会話の直近10往復を踏まえて返答。
- スマホ対応、改行、IME対応、送信中表示、新しい会話。
- 失敗時は入力文を復元。AIの返答を捏造した代替応答には切り替えない。
- 通常のフォーム送信を使わず、送信後も同じ画面に残る。
- 会話本文はタブのメモリー内のみ。localStorageやアプリDBに保存しない。

## 送信前の確認

1. 入力の原文は端末内に置き、検出用の別の文字列をNFKCで正規化する。全角、濁点結合、不可視文字や空白の表記をそろえる。
2. メール・電話・カード番号の候補・氏名の表明・地名・駅名・住所・学校名・勤務先・秘密情報などをルールと辞書で探す。
3. 正規化した位置を原文の文字位置に対応付け、原文のまま候補をマーキングする。重なった候補は結合する。
4. 候補をタップして選択・解除。「すべて隠す」も使える。初期状態は未選択。
5. 下の送信文で、選んだ範囲だけが **`[非表示]`** になることを確認する。確定するまで外部AIに送らない。
6. 確認した文章だけを送信・会話履歴へ追加する。通信失敗時にも原文ではなく、確認した送信文を入力欄へ戻す。

候補ゼロでも送信文を確認します。取消時は原文の入力欄に戻れます。原文のマーキングは `textContent` とDOMのテキストノードで作り、入力HTMLを実行しません。
選ばなかった候補は **原文のまま送られます**。検出には見落とし・誤検出があり、完全匿名化は保証しません。
氏名は「名前は〜です」などの表明が対象で、文中のすべての人物名を認識するものではありません。
**端末内AIによる文脈検出はまだ実装していません。** 次段階で、ルール検出と本人の確認の間に追加します。

## 情報の流れ

ブラウザー → このアプリの認証済みAPI → OpenAI Responses API。
APIキーはサーバー秘密変数。ブラウザー・Git・配布アーカイブへ含めません。
送信は `store:false`。OpenAI側のすべての保存・監視を無効にする保証ではありません。
アプリDBはユーザーIDと日付ごとの利用回数だけを記録します。1人1日60回、1入力2,000文字、入力合計12,000文字、直近10往復まで。
公開環境はSitesの認証を使用し、匿名のAPI実行は拒否します。作成時は本人限定です。
`reviewVersion` は古いクライアントを止める互換性管理です。本人が画面で確認したことや、個人情報が完全に除去されたことをサーバーへ証明するものではありません。サーバーは非表示前の原文・置換表を受け取りません。

## 開発

Node.js 24推奨（22.13以降のnode:sqliteが必要）。

```sh
npm ci
npm run dev:local
```

`http://127.0.0.1:5180/chat/` を開きます。ローカルは合成IDに固定し、localhostだけで待ち受けます。
OpenAI Developersの安全なキー設定フローで、このリポジトリの `.env.local` に `OPENAI_API_KEY` を設定します。ファイルはGit管理しません。
ローカルの利用回数は `.sites-runtime/chat-quota.sqlite` に保存します。

```sh
npm test
npx tsc --noEmit
npm run build
```

`public/chat/privacy.mjs` が正規化・文字位置対応・候補検出・選択後の置換、`public/chat/` がUI、`lib/chat.mjs` がプロバイダーと入力検証、`app/api/` が本番の認証とバインディング、`scripts/dev-chat.mjs` がローカル実行です。
GitHubへのpushとSitesへのデプロイは別です。秘密変数の更新後は再デプロイが必要です。
新しいAPIキーは作成時に選択した有効期間で失効します。今回の初期キーは24時間です。

参考：[OpenAI会話履歴のガイド](https://developers.openai.com/api/docs/guides/conversation-state)
