# ことばフィルター（仮称）

共有前の文章から、個人情報・機密情報の候補を**端末内で**検出するプロトタイプ。
GitHubリポジトリは `seira20071004-cyber/kotoba-filter` です。

## 使い方

1. 2,000文字までの文章を入力・貼り付け。
2. 「ライト」または「スタンダード」を選び、「ルール＋端末内AI」または「ルールのみ」でチェック。
3. 個人情報は初期選択で置換。スタンダードでは、説明を残して隠す具体値の候補と理由を確認し、隠すか内容を残すかを本人が選びます。値を切り出せない箇所は、手動指定または原文が残ることの確認が必要です。未確認の機密候補がある間はコピーできません。人物・組織の別表記や代名詞は、本人が確認して同じラベルにまとめられます。
4. `[人物1]` `[組織1]` など、種類と一貫性を保つラベルに置き換えた文章を確認してコピー。置換一覧と、機密候補の確認理由も表示します。対応表と理由はコピーしません。外部AIの回答を貼り付けて、この画面の対応表で元の値へ戻せます。

原文の表記を変えず、検出用の別文字列をNFKC正規化して全角・不可視文字などへ対応します。正規化は検出そのものではなく前処理です。
個人情報は専用モデルをWeb Workerで実行します。GPUはOpenAI Privacy Filter、CPUは日本語NER＋ルールです。スタンダードでは、WebLLM / Qwen2.5で機密の具体値も抽出します。この追加AIにはWebGPUが必要です。画面にはライトとスタンダードを提供します。フルセキュアは未提供です。初回に大きなモデルの取得・キャッシュと空きメモリーが必要です。全端末での動作は保証しません。

## 情報の境界

- 入力文・検出結果・機密キーワードはタブ内のメモリーだけで扱います。アプリのサーバーや外部AIへ送信せず、本文をDB・localStorage・履歴へ保存しません。
- モデルのファイルと実行用ライブラリーを外部配信先から取得する通信はあります。入力文をその通信へ付加しません。オフライン動作の保証ではありません。
- チャット機能は終了しました。旧 `/api/chat` も本文を読まず410を返し、外部AIへ転送しません。旧APIキーはアプリの実行に不要で、既存の秘密変数が残っていても参照しません。
- サイトのアクセス認証・公開範囲は以前の設定を保持します。本文の検出にログインAPIや外部チャットAPIは使いません。
- コピーは端末のクリップボードへ行います。貼り付け先への共有は本人の操作です。

## 限界と確認

完全な検出や匿名化、法的な営業秘密の判定は保証しません。見落とし・誤検出があり、「候補なし」も安全の保証ではありません。個人情報の候補は初期選択されます。機密候補は自動選択せず、本人が選んだ範囲のみ置換します。本人が残すと選んだ部分や見落とした情報は原文のまま残ります。ライトでは機密の具体値を確認しません。
会社固有のキーワード（2〜80文字・20件まで）と、原文中の語句を手動で隠す機能を使えます。
端末内AIの準備前・実行中・失敗時は加工欄を空にし、コピーを無効にします。使えない場合は本人が「ルールのみ」を選んで再チェックできます。自動では切り替えません。
原文・検出方法・キーワードを変更すると結果を無効にし、古い文章のコピーを防ぎます。

## 開発

Node.js 24推奨。

```sh
npm ci
npm run dev:local
```

`http://127.0.0.1:5180/chat/` を開きます。**APIキー・DB設定は不要**です。

```sh
npm test
npx tsc --noEmit
npm run build
```

- `public/chat/privacy.mjs`：正規化・原文位置対応・ルール候補・選択後の置換
- `public/chat/standard.mjs`：業務値ルール・AI引用の検証・未解決警告
- `public/chat/abstraction.mjs`：レベル、追加検出、重なりの分割、一貫したラベル、置換理由
- `public/chat/confidential.mjs`：文脈ルール、機密語、手動追加、AI結果の検証
- `public/chat/local-detector.mjs`：WebGPU・Workerの準備、停止、失敗処理
- `worker/confidential-worker.mjs`：端末内モデルの実行
- `public/chat/chat.js`：入力→検出→選択→コピーのUI
- `lib/retired-chat.mjs`：旧チャットAPIの無効化

個人情報Workerは `npm run pii:prepare`、機密確認Workerは `npm run local-ai:prepare` で再生成します。`npm run build` / `npm run dev` / `npm run dev:local` の前にも自動生成します。GitHubのソースには生成済みWorkerを含めず、`worker/` 配下のソースと固定依存関係から生成します。Transformers.js、ONNX Runtime、WebLLMのライセンスは同じフォルダーに含めています。
GitHubへのpushとSitesへのデプロイは別です。Sitesの既存DBスキーマは破壊的な削除をせず保持しますが、このツールではDBへ読み書きしません。
